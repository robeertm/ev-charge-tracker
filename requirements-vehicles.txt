# Vehicle-API connectors — every brand the app can talk to, in one file.
#
# WHY A SEPARATE FILE. These are baked into the container image (see
# Dockerfile) so a container install can talk to every supported car the
# moment it starts: no "package needed" tile, no install button, and
# nothing that lives only in the container's writable layer and vanishes
# on the next `docker compose pull`. Pulling a newer image brings newer
# connectors along with it — that is the whole point.
#
# They are NOT in requirements.txt because that file must stay installable
# on Python 3.11. hyundai-kia-connect-api declares Requires-Python >=3.12
# from 4.23.1 onward, so folding it into the core list would break every
# native install on Raspberry Pi OS bookworm. The native installer and the
# in-app updater therefore install this file BEST-EFFORT, one line at a
# time: a package that will not install on the local interpreter is
# skipped, and the app keeps the brands it can serve.

# Kia UVO / Hyundai Bluelink.
# >=5.2.1 (needs Python >=3.12; on 3.11 this line is skipped and the app
# routes users to the browser token). 5.x reads every EU car's cached
# status through a newer feed; 5.2.0 reported "charging" whenever that feed
# carried a remaining-charge time (cable out, 0 kW), which held the
# charging guard shut on every update. 5.2.1 fixes it.
#
# UPPER BOUNDS ON EVERY LINE. A rebuilt image used to pull whatever was
# newest: on 10 Nov 2026 this SDK jumped from 4.x to 5.x without anybody
# choosing it, and its new status format broke place names in the trip log.
# Every line is therefore capped below the next major version (for 0.x
# packages, where semver treats each minor as a major, below the next
# minor). Moving a cap is a deliberate change that runs the connector tests
# against the image built from it (scripts/check_dependency_bounds.py,
# promote workflow).
hyundai-kia-connect-api>=5.2.1,<6

# VW group. `carconnectivity` is the shared base; one connector per brand.
# All five are needed — the registry registers vw, skoda, seat, cupra AND
# audi, and each maps to its own connector type at runtime.

carconnectivity-connector-volkswagen<0.11
carconnectivity-connector-skoda<0.14
carconnectivity-connector-seatcupra<0.7
carconnectivity-connector-audi<0.4

aiohttp>=3.9,<4                # required by renault-api's async client
pypolestar>=1.0.0,<2           # Polestar
saic-ismart-client-ng>=0.5.0,<0.17  # MG (SAIC iSMART)
pySmartHashtag>=0.1.0,<0.16    # Smart #1 / #3
pyporscheconnectapi>=0.1.0,<0.3  # Porsche Connect
